# LOUPE 개발 로그

LOUPE(0.5.0 까지의 이름: Photo Organize)를 만들면서 받은 **요청과 피드백**, 그에 따라 **무엇을 바꿨는지**, **왜 그렇게 정했는지**, **어떻게 확인했는지**, **무엇이 남았는지**를 한곳에 모은 기록입니다.

새로 합류한 개발자 · 에이전트 · 리뷰어가 대화 기록 없이도 "왜 지금 이렇게 되어 있는가"를 알 수 있게 하는 것이 목적입니다.

| 셀렉 엔진의 계획 · 측정 원칙 | [docs/cull-engine/ROADMAP.md](cull-engine/ROADMAP.md) |

| 작업 규칙 (브랜치 · 릴리스 · 보안) | [AGENTS.md](../AGENTS.md) |

**읽는 법**

- 날짜는 UTC 입니다. "사용자"는 이 앱을 직접 쓰는 사진가이자 제품 책임자입니다.
- 요청은 요약했고, 판단에 중요한 표현은 원문 그대로 따옴표로 옮겼습니다.
- 항목마다 순서는 *요청 → 반영 → 결정과 이유 → 확인 → 남은 점* 입니다. 해당 없는 칸은 뺐습니다.
- PR 번호는 `MJ-best/exif-photo-organize` 의 PR 입니다. 모두 squash 머지라 main 의 커밋 하나가 PR 하나입니다.

## 2. 제품 원칙 — 사용자가 정한 것

첫 요청(11-01)과 이후 피드백에서 나온, 앞으로도 지켜야 할 방향입니다. 새 기능은 이 목록과 부딪히지 않는지 먼저 봅니다.

1. **정리와 셀렉에 집중.** "사진 편집기능은 없이 순전히 정리와 셀렉(별 1~5개를 단축키 F1~F5으로 눌러서 고르기)에 초점"
   - 예외는 0.7.1 의 크롭 · 수평 하나뿐입니다. 사용자가 직접 범위를 정했습니다: "컬러그레이딩 까지는 아니고 그냥 셀렉과 크롭, 가로 세로 맞추기 정도만"
2. **카드에서 외장 하드까지 한 흐름.** "1. 앱을 열고 2. sd카드를 꼽고 3. 앱을 통해 외장하드에 옮기고 동시에 정리하고 exif기반으로 태그정보를 만들어서 동시에 정리된 갤러리(미리보기)를 만들어"
3. **빠를 것.** "rust기반의 빠르고 성능좋은 사진 정리앱". 수만 장을 기준으로 잽니다.
4. **애플 「사진」 앱 같은 화면.** 처음 요청한 디자인입니다. 0.2.0 부터는 사용자가 준 그림을 따른 크림 · 코코아 테마가 기본입니다.
5. **사진가의 작품 활동을 돕는다.** "셀렉 > 셀렉된 작품사진을 폴더로 모음 > 폴더 단위로 … 라이트룸 등에서 편집"
6. **셀렉 도우미(자동 B컷 · A컷)가 사업의 핵심.** "이 기능을 고도화해서 사업화를 해보려고해", "유료로 업그레이드 가능하게 하려는 자동 B컷, 자동 A컷 추천기능"
7. **따로 라벨링하지 않는다.** 평소의 픽 · 거절 · 별점이 곧 학습 데이터입니다. 기준은 장면(인물 · 풍경 · 정물 …)마다 다릅니다: "인물/풍경/정물 등 상황(태그)에 따라서 다를꺼같아"
8. **원본은 건드리지 않는다.** 크롭은 카탈로그에만 기록하고, 지우기는 시스템 휴지통으로 옮깁니다. 가져오기는 체크섬으로 확인합니다.
9. **사진은 기기 밖으로 나가지 않는다.** 모든 모델이 앱 안에서 돕니다. 네트워크는 라이선스 확인에만 씁니다 (App Store · Android 판은 아예 없음).

## 3. 반복해서 나온 피드백 — 다시 생기지 않게 할 것

| 피드백 | 나온 때 | 지금 지키는 방법 |
|---|---|---|
| **사진을 가리지 말 것.** "그 액션이 중앙에 크게 나와서 사진을 잠깐 가리는데 … 그 0.1초가 너무 거슬려" | 0.2.5 | 알림은 사진 아래 띠에만 띄웁니다. 사진 위에 그리는 표시(B컷 근거, 구도 G)는 끌 수 있고, 글자끼리 · 배지와 겹치지 않게 놓습니다 (0.7.2). |
| **흐름이 직관적일 것.** "고를 사진에 있는건 내 기준으로 헷갈려 … 번잡한 느낌" | 0.2.4 | 새 목록이나 모드를 늘리지 않고, 사용자가 이미 보고 있는 화면(별점 있는 사진)에서 바로 하게 합니다. |
| **셀렉 도우미를 믿을 수 있을 것.** "ML기반으로 B컷 후보가 추천이 되는게 맞는지 모르겠어", "B컷후보가 갑자기 사라졌어", "B컷 가능성이라는 게이지를 해석하기가 어려워요" | 0.2.6 · 0.3.0 · 0.7.0 · 0.7.4 | 후보 수가 붕괴하지 않게 하한만 보정하고(불균형 라벨·삭제된 연사에서 95% 쏠림 방지), 정확도는 학습에 안 쓴 사진으로 재서 보여 줍니다 (0.3.0). B컷 · A컷마다 근거를 보여 주며 (0.7.0), 게이지는 왼쪽(B컷) ↔ 오른쪽(A컷)으로 방향을 명확히 합니다 (0.7.4). |
| **글자가 겹치지 않을 것.** "표시되는 레이아웃이 깔끔하지 않고 글씨가 겹치는 부분이 보여" | 0.7.2 | 위쪽 막대에 버튼을 더할 때는 *도구 먼저, 제목은 남는 자리에* 규칙을 지킵니다. 창 폭 960(최소) · 1200 · 1600, 정보 패널을 켜고 끈 상태에서 확인합니다. |
| **릴리스는 끝까지 확인해서 알려 줄 것.** "릴리즈 됐어?" (여러 번), "릴리즈 없다는데" | 0.1.0 ~ | 파일 4개가 다 올라간 것까지 확인한 뒤 릴리스 링크를 알립니다. 맥 업데이트용 터미널 명령도 함께 줍니다: "이전처럼 맥버전은 터미널로 업데이트 하게 명령어줘" |
| **설치 경고로 막히지 않을 것.** "악성코드 나오는거 때문에 설치가 안되고 있어" | 0.2.0 | 릴리스 노트와 README 에 *그래도 열기* 와 터미널 설치를 안내합니다. 근본 해결(Developer ID 공증)은 4절의 열린 과제입니다. |

## 4. 열린 과제

### 사용자가 해야 하는 것 (계정 · 결제 · 개인 정보가 걸려 있음)

- [ ] **Mac App Store 재제출 (2.5.1 비공개 API 수정 반영).**
  - Actions → **app-store** → *Run workflow* 를 실행해 `_CGSSetWindowBackgroundBlurRadius` 가 제거된 새 빌드(8)를 올립니다.
  - App Store Connect 의 0.7.3(또는 0.7.4) 버전에서 기존 빌드 7 대신 **새로 올라간 빌드(8)** 로 바꾸고 다시 심사에 제출합니다.
  - [listing.md](app-store/listing.md) 의 글과 스크린샷을 넣습니다. 스크린샷은 0.7.3 에서 새 그림으로 바뀌었으니, 이미 올린 것이 있으면 `docs/app-store/screenshots/` 의 것으로 바꿉니다.
  - **개인정보처리방침 URL** 은 [docs/app-store/privacy.md](app-store/privacy.md) 의 GitHub 주소(`https://github.com/MJ-best/exif-photo-organize/blob/main/docs/app-store/privacy.md`)를 넣으면 됩니다. 판매 사이트를 배포하면 사이트의 `/privacy` 로 바꿉니다.
  - 유료 앱 계약 · 은행 · 세금이 *활성* 인지도 확인합니다.
- [ ] **app-store 워크플로는 사용자가 직접 실행합니다** (Actions → app-store → Run workflow → 초록 버튼). 이 저장소의 자동화 권한으로는 실행 요청이 403 으로 막힙니다.
- [ ] **판매 사이트 배포.** Firebase 프로젝트, 토스페이먼츠 키, 공개 연락 이메일이 필요합니다 (`site/site.config.json`). 배포하면 개인정보처리방침 주소도 생깁니다.
- [ ] **Google Play.** 계정 검토가 끝나면 다음을 합니다:
  - 업로드 키를 만들고 GitHub 시크릿 4개를 넣습니다.
  - 테스터 12명 이상(이탈을 생각해 15명 권장)을 모아 14일 비공개 테스트를 합니다.
  - 결제 프로필을 만듭니다.
- [ ] **유료 기능의 범위 정하기.** 무료 체험 조건, 그리고 구도 판정을 유료로 묶을지를 정해야 합니다. 정하면 앱의 라이선스 확인에 넣습니다.
- [ ] **Apple Developer ID 공증.** 웹사이트판의 "악성 코드" 경고를 없앱니다. CI 는 준비되어 있고 인증서만 넣으면 됩니다.

### 개발 쪽

- [ ] **Google Play 스토어 스크린샷을 실제 사진 · 지금 버전으로 다시 찍기.** Play 스크린샷(`docs/play-store/graphics/phone-*` 등)이 예전 견본 그대로입니다. (Mac App Store 스크린샷 8장은 11-18 에 실제 사진 · 0.7.3 화면으로 교체 완료)
- [ ] **테마를 새 아이콘에 맞출지 정하기.** 크림 · 코코아 테마는 첫 아이콘에서 뽑은 색 그대로입니다 (사용자 결정 필요).
- [ ] **실제 촬영본으로 문턱값 맞추기.** 구도(3분할 · 기울기 · 헤드룸)와 눈 감음은 공개 샘플 사진과 합성 테스트로만 확인했습니다. 기준 데이터셋 v1 이 필요합니다 ([ROADMAP](cull-engine/ROADMAP.md) M1).
- [ ] **크롭을 XMP 로 내보내기.** 라이트룸에서 크롭이 이어지게 합니다 (0.7.1 의 남은 점).
- [ ] **관절에서 잘린 팔다리** 판정 (포즈 모델 필요). **여러 사람 중 누구** 의 문제인지 표시. **원근 가로선** 과 수평선 구분.
- [ ] **눈 감음 · 표정 소형 모델** (지금은 휴리스틱이라 웃는 눈을 감은 눈으로 볼 수 있음).
- [ ] **"같은 순간" 묶음.** 연사 3초를 넘어 임베딩과 시간으로 묶고, 묶음마다 A컷 1장을 고릅니다.
- [ ] **학습이 기본 기준보다 나쁘면** 자동으로 기본 기준 쪽으로 돌아가게 합니다 (M1).
- [ ] **안드로이드 실기기 확인.** 지금까지는 Robolectric 시뮬레이션뿐입니다. 고른 사진을 컴퓨터로 옮기는 기능도 아직 없습니다.
- [ ] **iOS · iPadOS 실기기 확인 및 Core ML(ANE) 가속.** macOS Xcode 시뮬레이터 · 실기기에서 UI, USB-C 외장 SSD/SD 카드 북마크, Instruments 메모리/발열을 확인하고, 추후 `crates/cull` 의 ONNX 추론을 Core ML(ANE) 백엔드로 확장합니다.
- [ ] **맥 App Store 판 실사용 확인.** TestFlight 에서 샌드박스 권한 기억, SD 카드 가져오기, 라이선스 칸 없음을 봅니다.

### 0.2.6 — 셀렉 도우미 정리 · A컷 후보 (11-04, #10)

- **피드백**: "B컷으로 골라서 제외하려는데 왜 아직고르지않은사진에 B컷이 계속 남아있는거야", "ML기반으로 B컷 후보가 추천이 되는게 맞는지 모르겠어. B컷 사진을 많이 골랐는데 B컷후보가 갑자기 사라졌어", "A컷 후보도 만들어줘"
- **반영**
  - *아직 고르지 않은 사진* 은 별점 · 픽 · 거절이 모두 없는 사진만 보여 줍니다. `X` 를 누르면 바로 빠집니다.
  - B컷 후보가 사라진 원인: 가장 심한 B컷부터 거절하다 보니 학습이 *"아주 심하게 흐린 것만 B컷"* 으로 잘못 배웠습니다. 이제 학습은 **어떤 사진이 B컷인지** 만 내 기준으로 바꿉니다. **몇 장이 B컷인지** 는 기본 기준을 내 판정으로 보정해 따릅니다 (`learn::anchor`). 시뮬레이션에서 후보 수는 고치기 전 1,202 → 41장이었고, 고친 뒤 897장이었습니다.
  - **A컷 후보** 를 넣었습니다: 고르지 않은 사진의 상위 15% (5–50% 조절). 연사는 베스트 한 장만 넣습니다.

### 0.3.0 — 셀렉 엔진 분리 · 내 셀렉 정확도 (11-05, #11)

- **요청**: "B컷후보 A컷후보를 찾는 모델에 대해서 따로 브랜치를 파서 전문화해보자. 이 기능을 고도화해서 사업화를 해보려고해", "내 셀렉 정확도 표시먼저 하자"
- **반영**
  - 엔진을 `crates/cull` 로 떼어 **BUSL 1.1** 로 바꿨습니다. 나머지는 MIT 그대로입니다.
  - `photoorg cull-eval` 을 넣었습니다: 판정을 5묶음으로 나눠 하나씩 가리고 맞히는 교차검증입니다. 지표는 AUC · B컷 정밀도/재현율 · *A컷을 B컷으로 잘못 올린 비율* 입니다.
  - 앱에 *내 셀렉 정확도* 창을 넣었습니다: 기본 기준 대비, 장면별, 기록 그래프.
- **결정과 이유**
  - 엔진만 BUSL 로 한 것은 사업의 차별점이 엔진이기 때문입니다.
  - v0.2.6 까지 MIT 로 나간 엔진은 되돌릴 수 없습니다. 그래서 경쟁력은 이후의 개선과 데이터에서 나와야 합니다.
  - **각 릴리스의 Change Date 를 그 날 + 4년으로 올립니다.** BUSL 은 *Change Date* 와 *공개일 + 4년* 중 이른 날에 MIT 가 되므로, 올리지 않으면 새 버전이 일찍 풀립니다. 체크리스트는 [LICENSING.md](../LICENSING.md) 에 있습니다.
  - *가장 비싼 실수* 는 A컷을 B컷으로 거르는 것이라, 이 비율을 따로 보여 줍니다.
- **확인**: 무작위가 섞인 판정에서는 학습이 기본 기준보다 정확도가 2%p 낮게 나왔습니다. 대신 A컷을 잘못 올린 비율은 26% → 16% 로 줄었습니다. 이 숫자를 그대로 보고했습니다.

### 0.7.0 — 구도 · 프레이밍 (11-15, #21)

- **요청** (유료 기능으로 생각하는 부분)
  - "여러 구도를 학습하고 해당 구도에서 벗어나는 사진을 B컷으로 학습되도록 머신러닝 알고리즘을 개선할 수 있어?"
  - "피사체와 배경을 분리하고 피사체의 위치와 구도, 초점을 확인하고 맞추는거야. 예를들어 3분할, 인물의 시선앞에 아이룸이 있는지, 헤드 스페이스가 있는지, 세로 기둥이 인물머리 뒤에 있는지 등"
  - "이걸 기준으로 B컷 추천 (근거가 되는 프레이밍, 초점 등 제시) > B컷 설정에서 3분할 기준을 빼는 등으로 개인 커스터마이즈 가능"
- **반영**
  - **인물 분할**: PP-HumanSeg (Apache-2.0, 192×192, 사진당 약 0.1초) 로 사람과 배경을 나눕니다 (`crates/cull/src/segment.rs`).
  - **구도 측정** (`composition.rs`, 분석 버전 4): 판정이 아니라 **원래 잰 값** 을 저장합니다 — 피사체 상자, 기준점(눈), 얼굴 방향, 머리 위 여백, 머리 뒤 세로선, 기울기, 피사체 · 배경 선명도. 그래서 기준을 바꾸거나 크롭해도 다시 분석하지 않습니다.
  - **특징 8개 추가 (16 → 24)**: 3분할 · 헤드룸 · 시선 앞 공간 · 머리 뒤 기둥/선 · 기울어짐 · 얼굴 잘림 · 배경에 초점 · 내 구도와 다름.
  - **내 구도 학습**: 같은 장면의 A컷 중 구도가 가까운 5장과의 거리를 특징으로 씁니다 (A컷 8장 이상일 때). 여러 구도를 쓰면 여러 무리로 기억하고, 어느 것과도 다른 사진을 B컷 쪽으로 올립니다.
  - **근거**: 정보 패널 *구도* 칸에 기준마다 잰 값과 판정을 보여 줍니다. 크게 보기에서 `G` 를 누르면 사진 위에 그립니다. A컷 후보에도 근거가 붙습니다.
  - **기준 끄기**: 설정의 *B컷으로 볼 기준* 에서 끈 기준은 특징을 0으로 만듭니다. 그래서 기본 기준 · 학습 · 이유 · 근거에서 모두 빠집니다.
- **결정과 이유**
  - 사람이 아닌 피사체용 돌출도 모델(U²-Net-p)은 tract 에서 사진당 2.5초라 뺐습니다. 대신 심도가 얕은 사진에서는 초점이 맞은 영역을 피사체로 봅니다.
  - *배경에 초점* 은 디테일 양이 아니라 **가장자리 선명도**(가장자리 화소의 RMS 라플라시안 ÷ 평균 기울기)로 잽니다. 디테일 양으로 재면 국기 · 나뭇잎처럼 무늬 많은 배경 앞의 인물을 *얼굴 초점 빗나감* 으로 잘못 봤습니다. 이 오판도 함께 고쳤습니다.
  - 기울기는 화면 가운데의 세로선(기둥 · 건물)을 수평선보다 먼저 봅니다. 버스 지붕 같은 원근선을 기울어짐으로 보던 문제를 줄이려는 것입니다.
  - 단체 사진은 기준점을 모든 눈의 평균으로 하고, 3분할 가중을 낮췄습니다 (단체는 가운데 구도가 자연스러움).
  - 문턱값은 `composition.rs` 의 `judge()` 에 모여 있습니다. 하나의 값이 아니라 *완만한 경사* (`ramp`) 로 판정해 경계에서 결과가 튀지 않게 했습니다.
- **확인**
  - 공개 저장소의 샘플 사진(OpenCV · dlib · face_recognition · Ultralytics 예제)에서 판정을 확인했습니다.
  - 인물을 흐리게 만든 사본으로 *배경에 초점* 을 확인했습니다 (원본 0, 사본 1.0).
  - 합성 테스트로 학습(규칙이 이유로 나오고 끌 수 있음, 내 구도를 배움)을 확인했습니다.
- **남은 점**: 실제 촬영본 · 판정으로 문턱값을 맞춰야 합니다. 관절 잘림, 여러 사람 중 누구인지, 원근 가로선 구분도 남았습니다 (4절).

### Mac App Store 2.5.1 비공개 API 거절 수정 (11-17, #27)

- **요청**
  - 사진 노출 · 셔터 속도 4대 경험칙(역수 법칙 `1/초점거리`, Sunny 16, Looney 11, 500 법칙) 포스팅을 보여 주며: "이건 사진설정의 기본을 담은 내용의 포스팅이야. 이 내용이 앱에 포함되어있어? 이론과 rule 기반으로 제안이 되고있는지 점검"
  - 이어서 Mac App Store 심사 결과 공유: "앱 안에 Apple이 허용하지 않는 비공개 API 호출이 들어 있어서 자동 검사에서 막혔어요. 제출: 11월 16일 오후 10:07, 빌드 0.7.3 (7) / 결과: 11월 17일 오후 6:00에 Apple 자동 메시지로 거절 / 위반 조항: 2.5.1 Performance: Software Requirements (macOS) / 문제가 된 API: `_CGSSetWindowBackgroundBlurRadius`"
- **원인**
  - `eframe` 이 쓰는 창 라이브러리 `winit 0.30.13`(`src/platform_impl/macos/ffi.rs`, `window_delegate.rs`)에 창 배경 블러용 비공개 CoreGraphics 함수 `CGSMainConnectionID` 와 `CGSSetWindowBackgroundBlurRadius` 가 선언되어 있고, `WindowDelegate::new` 가 실행 시점에 `if attrs.blur { delegate.set_blur(attrs.blur); }` 로 분기합니다.
  - LOUPE 는 창 블러를 전혀 쓰지 않지만(`attrs.blur == false`), `WindowDelegate::new` 가 구조체 값을 실행 시점에 받아 분기하므로 링커가 죽은 코드로 지우지 못하고 Mach-O 바이너리의 동적 심볼 임포트 테이블에 `_CGSSetWindowBackgroundBlurRadius` 와 `_CGSMainConnectionID` 를 남겼습니다.
- **반영**
  - `crates/app/src/main.rs` 에 macOS(`aarch64`, `x86_64`)용 `global_asm!` 으로 `_CGSMainConnectionID` 와 `_CGSSetWindowBackgroundBlurRadius` 를 `.private_extern` 빈 함수(no-op, 0 반환)로 정의했습니다. 링커가 `CoreGraphics.framework` 대신 실행 파일 내부의 `.private_extern` 심볼로 연결하므로 동적 임포트 테이블에 들어가지 않고, 이어서 `strip -x` 가 지역(non-global) 심볼 이름까지 바이너리에서 완전히 지웁니다.
  - `scripts/macos-bundle.sh` 에서 `LOUPE.app/Contents/MacOS/photo-organize` 에 `strip -x` 를 실행한 뒤 `grep -aqE "CGSSetWindowBackgroundBlurRadius|CGSMainConnectionID"` 검사를 넣어, 두 문자열이 바이너리 어디에라도 남아 있으면 빌드가 즉시 실패하게 했습니다.
- **결정과 이유**
  - `winit` 전체(약 3 MB)를 저장소에 복제(vendor)하는 대신, 바이너리 크레이트에 `.private_extern` 스텁과 `strip -x` + 바이너리 문자열 검증을 넣었습니다. 서드파티 코드를 통째로 떠안지 않으면서도 심볼 테이블과 문자열 테이블 양쪽에서 해당 이름을 완전히 없앨 수 있고, 매 빌드마다 스크립트가 자동으로 검사합니다.
- **확인**
  - `llvm-mc` · `llvm-nm` 으로 `arm64-apple-macosx11.0.0` 및 `x86_64-apple-macosx11.0.0` 오브젝트에서 두 심볼이 `private external` 로 생성되는 것과 `strip` 뒤 바이너리에서 문자열이 완전히 사라지는 것을 확인했습니다.
  - PR 의 `macos` 빌드(`build.yml`)와 `app-store` 미리 확인(`app-store.yml --dry-run`)에서 실제 macOS 러너가 유니버설 바이너리를 만들고 `scripts/macos-bundle.sh` 의 `grep -aqE` 검사를 통과하는지 확인합니다.
- **남은 점**
  - 머지 뒤 사용자가 Actions → **app-store** → *Run workflow* 를 실행해 새 빌드(8)를 올리고, App Store Connect 의 0.7.3 버전에서 빌드 8 로 바꿔 다시 심사에 제출해야 합니다.

### 0.7.4 — 셀렉 도우미 왼쪽(B컷) ↔ 오른쪽(A컷) 게이지 · `learn::anchor` 점수 쏠림 수정 (11-21, #30)

- **피드백** (스크린샷: 정보 패널에 `B컷 가능성 94%` 주황 막대가 오른쪽 끝까지 차 있고, 그 바로 아래에 초록색 `가장 잘 나온 사진 상위 4% · A컷 후보` 가 함께 표시된 화면): "B컷 가능성이라는 게이지를 해석하기가 어려워요. 왜냐면 B컷 가능성이 높은건가? 아님 가능성이 낮아서 A컷이라는건가? 이게 모호해. 게이지가 왼쪽이면 B컷일 가능성이 높은거고 오른쪽이면 A컷일 가능성이 높다는 것을 알 수 있게 해줘"
- **반영 (게이지)**
  - 데스크톱 정보 패널(`crates/app/src/views/info.rs`)과 안드로이드 사진 보기 정보 패널(`android/.../ViewerScreen.kt`)의 단일 방향 `B컷 가능성` 막대를 **왼쪽 `← B컷 XX%` ↔ 오른쪽 `A컷 YY% →` 스펙트럼 게이지**로 바꿨습니다.
  - 막대 배경을 왼쪽 주황(B컷) → 가운데 중립 → 오른쪽 초록(A컷) 그라데이션으로 깔고, 세로 기준선(`1 - B컷 후보 기준`)에서 현재 위치(`1 - b_prob`) 방향으로 채운 뒤 원형 마커를 표시합니다. 마우스를 올리면 기준선 의미를 안내합니다.
  - `README.md` 의 정보 패널 설명도 새 게이지에 맞게 고쳤습니다.
- **결정과 이유 (게이지)**
  - 기존 막대는 B컷 가능성이 높을수록 오른쪽으로 채워져, 보통의 점수/품질 막대(오른쪽 = 좋음)와 방향이 반대라 직관과 어긋났습니다.
  - 양끝에 `← B컷 XX%` · `A컷 YY% →` 를 함께 두고 합이 항상 100%가 되게 하며, 해당 쪽만 강조 색과 굵은 글씨로 표시해 0.1초 만에 방향을 읽을 수 있게 했습니다.
  - 채움 기준점을 50%가 아닌 B컷 후보 기준선(`1 - cull_threshold/100`)으로 잡아, 사용자가 기준 슬라이더를 30~90% 사이 어느 값으로 바꾸더라도 기준선 왼쪽 = B컷 후보(주황), 오른쪽 = 후보 아님/A컷 쪽(중립·초록)이 항상 일치하게 했습니다.
- **확인 (게이지)**
  - `cargo fmt --all`, `cargo clippy --workspace --all-targets` (수정한 `info.rs` 경고 0), `cargo test --workspace`, `cargo test -p photoorg-app --no-default-features` 통과 (새 단위 테스트 `gauge_places_b_left_and_a_right`, `gauge_percentages_always_sum_to_100` 포함).
  - 실제 `egui` 렌더러로 크림·코코아 테마의 5가지 게이지 상태(`B 94%`, `B 62%`, `B 45%`, `A 92%`, `50/50`)와 창 폭 960·1200·1600, 정보 패널 켜짐·꺼짐 화면을 직접 렌더링해 글자 겹침과 사진 가림이 없음을 확인했습니다.

#### `learn::anchor` 점수 쏠림 수정

- **요청**: 앞선 스크린샷(초점 `6.0` · 상위 4% A컷 후보 사진이 `B컷 94%` 로 표시, 미결정 `16,033장` 중 `15,435장`(96.3%)이 B컷 후보)의 원인으로 지목된 보정 쏠림에 대해: `"learn::anchor 점수 쏠림까지 함께 점검·수정"`
- **원인**
  - 기존 `learn::anchor` 는 `strictness = ((actual + 3) / (expected + 3)).clamp(0.2, 5.0)`, `target = (prior_open * strictness).clamp(0.001, 0.95)` 를 구한 뒤 `fit` 모델의 절편 `b` 를 무조건 `mean(open) == target` 이 되도록 옮겼습니다.
  - 거절(`X`)이 픽(`P` · 별점)보다 훨씬 많은 라이브러리(`B ≫ A`, 예: 사용자 `A 112 / B 698`)에서는 기본 기준이 잘 맞더라도 `actual / expected` 가 최대 5배까지 커집니다.
  - 여기에 휴지통을 비워 삭제된 B컷(`learn_memory`, `gone = true`)은 연사 묶음에서 제외되어(`burst_rel = 0`, `not_best = 0`) `expected` 가 더 낮아지는 반면, 남아 있는 미결정 사진(`open`)은 연사 비베스트 프레임 때문에 `prior_open` 이 높게 유지되어 곱이 `0.95` 상한에 닿았습니다. 그 결과 상위 4% 선명한 A컷까지 `B컷 92~100%` 로 쏠렸습니다.
  - 반대로 별점 위주(`A ≫ B`) 흐름에서는 `actual / expected` 가 `0.2` 하한에 걸려 `anchor` 가 절편을 과도하게 끌어내리면서 B컷 재현율과 후보 목록이 붕괴(재현율 4.0%, 후보 7.1%)했습니다.
- **반영**
  - `crates/cull/src/learn.rs` 의 `anchor()` 를 양방향 강제 이동에서 **하한 붕괴 방지(collapse floor guard)** 로 바꿨습니다. `strictness` 상한을 `5.0 → 1.0` 으로 낮추고 `floor = (prior_open * strictness).clamp(0.001, 0.65)` 로 둔 뒤, `fit_open >= floor` 이면 클래스 균형 `fit` 의 절편을 그대로 쓰고, `fit_open < floor`(가장 심한 B컷부터 거절할 때 생기는 후보 붕괴)일 때만 `b` 를 위로 올립니다.
  - 회귀 테스트 2건(`imbalanced_b_labels_and_deleted_bursts_do_not_skew_scores`, `star_heavy_a_labels_do_not_collapse_candidates`)을 추가하고, 기존 취향 테스트 2건(`learns_user_taste`, `deleted_photos_still_teach_but_leave_bursts`)의 기준을 실제 60% 문턱 이상으로 강화했습니다(`p(500) > 0.7`, `p(501) < 0.15`; 기존에는 옛 `anchor` 가 `p(500)` 을 ~0.54로 끌어내려 `0.45` 기준만 검사하고 있었습니다).
  - `Analysis` 저장 형식은 그대로이므로 `ANALYSIS_VERSION` 은 올리지 않습니다. 앱이 라이브러리를 열 때 `ensure_analysis` 가 자동으로 재채점(`start_rescore`)을 돌려 이미지 재분석 없이 새 점수가 바로 반영됩니다.
  - 0.7.4 릴리스(`Cargo.toml`, `docs/releases/v0.7.4.md`)와 함께 셀렉 엔진의 BUSL 1.1 Change Date 를 `2030-11-21` 로 올렸습니다(`crates/cull/LICENSE`, `LICENSING.md`, `README.md`).
- **결정과 이유**
  - 클래스 균형 로지스틱 회귀 `fit()` 이 이미 `B : A` 표본 수 비율과 무관하게 50% 경계를 A컷과 B컷 사이에 둡니다(`cross_validate` 도 0.5 기준). `anchor` 가 양방향으로 평균을 강제 덮어쓰면 불균형 라벨에서 오히려 경계를 망가뜨립니다.
  - 검토 후 폐기한 대안:
    - 클래스 균형 `strictness = 0.5 / (0.5 * (p_b + p_a))` — 기본 기준이 완벽해도 라이브러리 실제 B컷 비율이 0.5 미만이면 수학적으로 최대 2.5배 상향 편향되어 폐기.
    - 무조건 `target = prior_open` — 취향 학습(`prior_open = 0.03` vs 실제 `0.25`)이나 깐깐한 눈 기준(`0.25` vs `0.55`)을 뭉개 버려 폐기.

- **반영**
  - **Rust 브릿지 (`crates/ios/src/lib.rs`)**:
    - `OpBarrier` · RAII `OpGuard` 를 모든 DB/장시간 FFI 메서드에 적용하고, `suspend()` 가 진행 중인 작업을 최대 4초 드레인한 뒤 WAL `checkpoint_truncate()` · 커넥션 드랍을 수행하도록 수정. `learn_locked()` · `reload_locked()` 가 상주 `self.catalog` 커넥션을 재사용해 추적되지 않는 SQLite 커넥션이 `suspend()` 를 넘어 살아남는 `0xdead10cc` 누수를 봉쇄.
