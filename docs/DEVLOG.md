# LOUPE 개발 로그

LOUPE(0.5.0 까지의 이름: Photo Organize)를 만들면서 받은 **요청과 피드백**, 그에 따라 **무엇을 바꿨는지**, **왜 그렇게 정했는지**, **어떻게 확인했는지**, **무엇이 남았는지**를 한곳에 모은 기록입니다.

새로 합류한 개발자 · 에이전트 · 리뷰어가 대화 기록 없이도 "왜 지금 이렇게 되어 있는가"를 알 수 있게 하는 것이 목적입니다.

| 버전마다 바뀐 것 (사용자용) | [docs/releases/](releases/) |
| 셀렉 엔진의 계획 · 측정 원칙 | [docs/cull-engine/ROADMAP.md](cull-engine/ROADMAP.md) |

| 스토어 · 판매 사이트 | [Mac App Store](app-store/README.md) · [Google Play](play-store/README.md) · [판매 사이트](../site/README.md) |
| 작업 규칙 (브랜치 · 릴리스 · 보안) | [AGENTS.md](../AGENTS.md) |

**읽는 법**

- 날짜는 UTC 입니다. "사용자"는 이 앱을 직접 쓰는 사진가이자 제품 책임자입니다.
- 요청은 요약했고, 판단에 중요한 표현은 원문 그대로 따옴표로 옮겼습니다.
- 항목마다 순서는 *요청 → 반영 → 결정과 이유 → 확인 → 남은 점* 입니다. 해당 없는 칸은 뺐습니다.
- PR 번호는 `MJ-best/exif-photo-organize` 의 PR 입니다. 모두 squash 머지라 main 의 커밋 하나가 PR 하나입니다.

## 2. 제품 원칙 — 사용자가 정한 것

첫 요청(11-01)과 이후 피드백에서 나온, 앞으로도 지켜야 할 방향입니다. 새 기능은 이 목록과 부딪히지 않는지 먼저 봅니다.

1. **정리와 셀렉에 집중.** "사진 편집기능은 없이 순전히 정리와 셀렉(별 1~5개를 단축키 F1~F5으로 눌러서 고르기)에 초점"
   - 예외는 0.7.1 의 크롭 · 수평 하나뿐입니다. 사용자가 직접 범위를 정했습니다: "컬러그레이딩 까지는 아니고 그냥 셀렉과 크롭, 가로 세로 맞추기 정도만"
2. **카드에서 외장 하드까지 한 흐름.** "1. 앱을 열고 2. sd카드를 꼽고 3. 앱을 통해 외장하드에 옮기고 동시에 정리하고 exif기반으로 태그정보를 만들어서 동시에 정리된 갤러리(미리보기)를 만들어"
3. **빠를 것.** "rust기반의 빠르고 성능좋은 사진 정리앱". 수만 장을 기준으로 잽니다.
4. **애플 「사진」 앱 같은 화면.** 처음 요청한 디자인입니다. 0.2.0 부터는 사용자가 준 그림을 따른 크림 · 코코아 테마가 기본입니다.
5. **사진가의 작품 활동을 돕는다.** "셀렉 > 셀렉된 작품사진을 폴더로 모음 > 폴더 단위로 … 라이트룸 등에서 편집"
6. **셀렉 도우미(자동 B컷 · A컷)가 사업의 핵심.** "이 기능을 고도화해서 사업화를 해보려고해", "유료로 업그레이드 가능하게 하려는 자동 B컷, 자동 A컷 추천기능"
7. **따로 라벨링하지 않는다.** 평소의 픽 · 거절 · 별점이 곧 학습 데이터입니다. 기준은 장면(인물 · 풍경 · 정물 …)마다 다릅니다: "인물/풍경/정물 등 상황(태그)에 따라서 다를꺼같아"
8. **원본은 건드리지 않는다.** 크롭은 카탈로그에만 기록하고, 지우기는 시스템 휴지통으로 옮깁니다. 가져오기는 체크섬으로 확인합니다.
9. **사진은 기기 밖으로 나가지 않는다.** 모든 모델이 앱 안에서 돕니다. 네트워크는 라이선스 확인에만 씁니다 (App Store · Android 판은 아예 없음).

## 3. 반복해서 나온 피드백 — 다시 생기지 않게 할 것

| 피드백 | 나온 때 | 지금 지키는 방법 |
|---|---|---|
| **사진을 가리지 말 것.** "그 액션이 중앙에 크게 나와서 사진을 잠깐 가리는데 … 그 0.1초가 너무 거슬려" | 0.2.5 | 알림은 사진 아래 띠에만 띄웁니다. 사진 위에 그리는 표시(B컷 근거, 구도 G)는 끌 수 있고, 글자끼리 · 배지와 겹치지 않게 놓습니다 (0.7.2). |
| **흐름이 직관적일 것.** "고를 사진에 있는건 내 기준으로 헷갈려 … 번잡한 느낌" | 0.2.4 | 새 목록이나 모드를 늘리지 않고, 사용자가 이미 보고 있는 화면(별점 있는 사진)에서 바로 하게 합니다. |
| **셀렉 도우미를 믿을 수 있을 것.** "ML기반으로 B컷 후보가 추천이 되는게 맞는지 모르겠어", "B컷후보가 갑자기 사라졌어" | 0.2.6 · 0.3.0 · 0.7.0 | 후보 수가 학습 전후로 급변하지 않게 기준점을 보정합니다. 정확도는 학습에 안 쓴 사진으로 재서 보여 줍니다 (0.3.0). B컷 · A컷마다 근거를 보여 줍니다 (0.7.0). |
| **글자가 겹치지 않을 것.** "표시되는 레이아웃이 깔끔하지 않고 글씨가 겹치는 부분이 보여" | 0.7.2 | 위쪽 막대에 버튼을 더할 때는 *도구 먼저, 제목은 남는 자리에* 규칙을 지킵니다. 창 폭 960(최소) · 1200 · 1600, 정보 패널을 켜고 끈 상태에서 확인합니다. |
| **릴리스는 끝까지 확인해서 알려 줄 것.** "릴리즈 됐어?" (여러 번), "릴리즈 없다는데" | 0.1.0 ~ | 파일 4개가 다 올라간 것까지 확인한 뒤 릴리스 링크를 알립니다. 맥 업데이트용 터미널 명령도 함께 줍니다: "이전처럼 맥버전은 터미널로 업데이트 하게 명령어줘" |
| **설치 경고로 막히지 않을 것.** "악성코드 나오는거 때문에 설치가 안되고 있어" | 0.2.0 | 릴리스 노트와 README 에 *그래도 열기* 와 터미널 설치를 안내합니다. 근본 해결(Developer ID 공증)은 4절의 열린 과제입니다. |

### 0.1.0 — 첫 앱 (11-01, #1)

- **요청**
  - SD 카드 사진을 외장 하드로 옮기는데 정리 · 셀렉 · 태그가 번거롭습니다. "같은걸 찍어도 RAW도 따로 보관하는데 뭐가 원본인지도 어렵기도 해"
  - EXIF(날짜 · 카메라 · ISO · 렌즈 mm · 조리개)로 빠르게 거르고 싶습니다.
  - 흐름은 앱을 열고 카드를 꽂으면 옮기면서 정리 · 태그 · 미리보기까지 한 번에.
  - 편집 없이, F1~F5 별점으로 셀렉합니다.

### 0.7.0 — 구도 · 프레이밍 (11-15, #21)

- **요청** (유료 기능으로 생각하는 부분)
  - "여러 구도를 학습하고 해당 구도에서 벗어나는 사진을 B컷으로 학습되도록 머신러닝 알고리즘을 개선할 수 있어?"
  - "피사체와 배경을 분리하고 피사체의 위치와 구도, 초점을 확인하고 맞추는거야. 예를들어 3분할, 인물의 시선앞에 아이룸이 있는지, 헤드 스페이스가 있는지, 세로 기둥이 인물머리 뒤에 있는지 등"
  - "이걸 기준으로 B컷 추천 (근거가 되는 프레이밍, 초점 등 제시) > B컷 설정에서 3분할 기준을 빼는 등으로 개인 커스터마이즈 가능"
- **반영**
  - **인물 분할**: PP-HumanSeg (Apache-2.0, 192×192, 사진당 약 0.1초) 로 사람과 배경을 나눕니다 (`crates/cull/src/segment.rs`).
  - **구도 측정** (`composition.rs`, 분석 버전 4): 판정이 아니라 **원래 잰 값** 을 저장합니다 — 피사체 상자, 기준점(눈), 얼굴 방향, 머리 위 여백, 머리 뒤 세로선, 기울기, 피사체 · 배경 선명도. 그래서 기준을 바꾸거나 크롭해도 다시 분석하지 않습니다.
  - **특징 8개 추가 (16 → 24)**: 3분할 · 헤드룸 · 시선 앞 공간 · 머리 뒤 기둥/선 · 기울어짐 · 얼굴 잘림 · 배경에 초점 · 내 구도와 다름.
  - **내 구도 학습**: 같은 장면의 A컷 중 구도가 가까운 5장과의 거리를 특징으로 씁니다 (A컷 8장 이상일 때). 여러 구도를 쓰면 여러 무리로 기억하고, 어느 것과도 다른 사진을 B컷 쪽으로 올립니다.
  - **근거**: 정보 패널 *구도* 칸에 기준마다 잰 값과 판정을 보여 줍니다. 크게 보기에서 `G` 를 누르면 사진 위에 그립니다. A컷 후보에도 근거가 붙습니다.
  - **기준 끄기**: 설정의 *B컷으로 볼 기준* 에서 끈 기준은 특징을 0으로 만듭니다. 그래서 기본 기준 · 학습 · 이유 · 근거에서 모두 빠집니다.
- **결정과 이유**
  - 사람이 아닌 피사체용 돌출도 모델(U²-Net-p)은 tract 에서 사진당 2.5초라 뺐습니다. 대신 심도가 얕은 사진에서는 초점이 맞은 영역을 피사체로 봅니다.
  - *배경에 초점* 은 디테일 양이 아니라 **가장자리 선명도**(가장자리 화소의 RMS 라플라시안 ÷ 평균 기울기)로 잽니다. 디테일 양으로 재면 국기 · 나뭇잎처럼 무늬 많은 배경 앞의 인물을 *얼굴 초점 빗나감* 으로 잘못 봤습니다. 이 오판도 함께 고쳤습니다.
  - 기울기는 화면 가운데의 세로선(기둥 · 건물)을 수평선보다 먼저 봅니다. 버스 지붕 같은 원근선을 기울어짐으로 보던 문제를 줄이려는 것입니다.
  - 단체 사진은 기준점을 모든 눈의 평균으로 하고, 3분할 가중을 낮췄습니다 (단체는 가운데 구도가 자연스러움).
  - 문턱값은 `composition.rs` 의 `judge()` 에 모여 있습니다. 하나의 값이 아니라 *완만한 경사* (`ramp`) 로 판정해 경계에서 결과가 튀지 않게 했습니다.
- **확인**
  - 공개 저장소의 샘플 사진(OpenCV · dlib · face_recognition · Ultralytics 예제)에서 판정을 확인했습니다.
  - 인물을 흐리게 만든 사본으로 *배경에 초점* 을 확인했습니다 (원본 0, 사본 1.0).
  - 합성 테스트로 학습(규칙이 이유로 나오고 끌 수 있음, 내 구도를 배움)을 확인했습니다.
- **남은 점**: 실제 촬영본 · 판정으로 문턱값을 맞춰야 합니다. 관절 잘림, 여러 사람 중 누구인지, 원근 가로선 구분도 남았습니다 (4절).

### Mac App Store 2.5.1 비공개 API 거절 수정 (11-17, #27)

- **요청**
  - 사진 노출 · 셔터 속도 4대 경험칙(역수 법칙 `1/초점거리`, Sunny 16, Looney 11, 500 법칙) 포스팅을 보여 주며: "이건 사진설정의 기본을 담은 내용의 포스팅이야. 이 내용이 앱에 포함되어있어? 이론과 rule 기반으로 제안이 되고있는지 점검"
  - 이어서 Mac App Store 심사 결과 공유: "앱 안에 Apple이 허용하지 않는 비공개 API 호출이 들어 있어서 자동 검사에서 막혔어요. 제출: 11월 16일 오후 10:07, 빌드 0.7.3 (7) / 결과: 11월 17일 오후 6:00에 Apple 자동 메시지로 거절 / 위반 조항: 2.5.1 Performance: Software Requirements (macOS) / 문제가 된 API: `_CGSSetWindowBackgroundBlurRadius`"
- **원인**
  - `eframe` 이 쓰는 창 라이브러리 `winit 0.30.13`(`src/platform_impl/macos/ffi.rs`, `window_delegate.rs`)에 창 배경 블러용 비공개 CoreGraphics 함수 `CGSMainConnectionID` 와 `CGSSetWindowBackgroundBlurRadius` 가 선언되어 있고, `WindowDelegate::new` 가 실행 시점에 `if attrs.blur { delegate.set_blur(attrs.blur); }` 로 분기합니다.
  - LOUPE 는 창 블러를 전혀 쓰지 않지만(`attrs.blur == false`), `WindowDelegate::new` 가 구조체 값을 실행 시점에 받아 분기하므로 링커가 죽은 코드로 지우지 못하고 Mach-O 바이너리의 동적 심볼 임포트 테이블에 `_CGSSetWindowBackgroundBlurRadius` 와 `_CGSMainConnectionID` 를 남겼습니다.
- **반영**
  - `crates/app/src/main.rs` 에 macOS(`aarch64`, `x86_64`)용 `global_asm!` 으로 `_CGSMainConnectionID` 와 `_CGSSetWindowBackgroundBlurRadius` 를 `.private_extern` 빈 함수(no-op, 0 반환)로 정의했습니다. 링커가 `CoreGraphics.framework` 대신 실행 파일 내부의 `.private_extern` 심볼로 연결하므로 동적 임포트 테이블에 들어가지 않고, 이어서 `strip -x` 가 지역(non-global) 심볼 이름까지 바이너리에서 완전히 지웁니다.
  - `scripts/macos-bundle.sh` 에서 `LOUPE.app/Contents/MacOS/photo-organize` 에 `strip -x` 를 실행한 뒤 `grep -aqE "CGSSetWindowBackgroundBlurRadius|CGSMainConnectionID"` 검사를 넣어, 두 문자열이 바이너리 어디에라도 남아 있으면 빌드가 즉시 실패하게 했습니다.
- **결정과 이유**
  - `winit` 전체(약 3 MB)를 저장소에 복제(vendor)하는 대신, 바이너리 크레이트에 `.private_extern` 스텁과 `strip -x` + 바이너리 문자열 검증을 넣었습니다. 서드파티 코드를 통째로 떠안지 않으면서도 심볼 테이블과 문자열 테이블 양쪽에서 해당 이름을 완전히 없앨 수 있고, 매 빌드마다 스크립트가 자동으로 검사합니다.
- **확인**
  - `llvm-mc` · `llvm-nm` 으로 `arm64-apple-macosx11.0.0` 및 `x86_64-apple-macosx11.0.0` 오브젝트에서 두 심볼이 `private external` 로 생성되는 것과 `strip` 뒤 바이너리에서 문자열이 완전히 사라지는 것을 확인했습니다.
  - PR 의 `macos` 빌드(`build.yml`)와 `app-store` 미리 확인(`app-store.yml --dry-run`)에서 실제 macOS 러너가 유니버설 바이너리를 만들고 `scripts/macos-bundle.sh` 의 `grep -aqE` 검사를 통과하는지 확인합니다.
- **남은 점**
  - 머지 뒤 사용자가 Actions → **app-store** → *Run workflow* 를 실행해 새 빌드(8)를 올리고, App Store Connect 의 0.7.3 버전에서 빌드 8 로 바꿔 다시 심사에 제출해야 합니다.
