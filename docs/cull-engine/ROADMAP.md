# 셀렉 엔진 고도화 로드맵

목표: **유료 데스크톱 앱 Photo Organize 의 핵심 차별점** — *"내 기준을 배우는 셀렉"*. 촬영 직후 수천 장에서 B컷을 걷어 내고 A컷을 먼저 보여 주며, 쓸수록 그 사진가의 기준에 맞춰집니다.

엔진은 `crates/cull` (`photoorg-cull`) 에 있고 [BUSL 1.1](../../crates/cull/LICENSE) 로 배포합니다 ([라이선스 구성](../../LICENSING.md)).

## 1. 지금의 엔진 (0.3.0 기준)

| 단계 | 내용 |
|---|---|
| 분석 (사진마다 1회) | 내장 미리보기 1600px → 초점(8×8 영역 최대 라플라시안 · 전체), 흔들림(구조 텐서 방향성), 노출(클리핑 · 밝기), 얼굴(YuNet) · 얼굴 초점 · 눈 뜸(랜드마크 주변 윤곽 휴리스틱), 장면(MobileNetV2 + 얼굴 크기), dHash |
| 라이브러리 단위 | 장면 안 선명도 백분위, 연사 묶음(3초 · dHash) 과 순위, 14개 특징 |
| 판단 | 기본 기준(손으로 맞춘 로지스틱) → 내 판정(픽 · 거절 · 별점)으로 규제 로지스틱 회귀(전체 → 장면별), 기준점 보정(`learn::anchor`) |
| 결과 | B컷 확률 · 이유, A컷 후보(상위 n% · 연사 베스트), 학습 상태 |
| 측정 | `eval::evaluate` / `photoorg cull-eval <라이브러리>` — 접어서(k-fold) 안 본 사진으로 AUC · B컷 정밀도/재현율 · A컷 정밀도 · 후보 비율, 기본 기준 vs 학습 |

강점: 기기 안에서만 동작(사진이 밖으로 나가지 않음), 라벨링 없이 평소 셀렉이 곧 학습, 장면별 기준, 수만 장도 학습이 1초 안팎.

약점: 판단 근거가 *기술적 품질*(초점 · 흔들림 · 노출 · 눈)에 머묾 — 표정 · 구도 · 순간 · 피사체 같은 *작품성*은 모름. 눈 감음은 휴리스틱. 연사가 아닌 "같은 순간" 묶음이 약함.

## 2. 원칙: 재고 나서 고친다

모든 변경은 `photoorg cull-eval` 숫자로 판단합니다.

- **기준 데이터셋 (가장 먼저)**: 실제 촬영본 + 사진가의 실제 판정. 작가 본인 라이브러리부터, 베타 사진가들의 *동의를 받은* 판정(사진 대신 특징값과 라벨만 받아도 됨)으로 넓힙니다. 장면(인물 · 웨딩 · 풍경 · 스냅 · 행사)과 카메라별로 나눠 봅니다.
- **지표**: B컷 — AUC, 기준 60%에서의 정밀도 · 재현율, *잘못 거른 A컷 비율*(가장 비싼 실수). A컷 — 상위 k 정밀도. 사용성 — 후보 비율이 학습 전후로 급변하지 않을 것.
- **회귀 테스트**: 합성 데이터 테스트(`learning_beats_the_prior_on_unseen_photos`, `candidates_survive_rejecting_the_worst`)는 CI 에서 항상, 실제 기준 데이터셋은 릴리스 전마다.

## 3. 단계별 계획

### M1 — 측정 기반 (진행 중)
- [x] 엔진을 독립 crate 로 분리, BUSL 1.1
- [x] 교차검증 평가 (`cull-eval`, JSON 출력)
- [ ] 기준 데이터셋 v1: 작가 라이브러리 1–2만 장 + 판정, 장면별 리포트를 문서로 남김
- [x] 앱에 "내 셀렉 정확도" — 후보 바 · 설정에서 열고, 판정이 바뀌면 뒤에서 다시 잼, 기록 그래프 (카탈로그에 30회 보관)
- [ ] 학습이 기본 기준보다 나쁘게 재지면(교차검증) 자동으로 기본 기준 쪽으로 — 평가 결과로 모델 고르기

### M2 — 개인화 강화 (가장 큰 차별점)
- [ ] **이미지 임베딩 특징**: 이미 돌고 있는 MobileNetV2 의 마지막 풀링 출력(1280차원)을 32–64차원으로 줄여 저장 → 개인 모델이 *피사체 · 구도 · 분위기* 취향까지 학습 (기술 특징 14 + 임베딩)
- [ ] **"같은 순간" 묶음**: 3초 연사를 넘어, 임베딩 유사도 + 시간으로 비슷한 컷 묶음 → 묶음마다 A컷 후보 1장 (웨딩 · 행사에서 효과 큼)
- [ ] 판정이 적을 때의 안정성: 사진가 그룹(장르)별 사전 모델 → 개인 모델로 이어 학습

### M3 — 판단력 강화
- [ ] 눈 감음 / 표정 분류 소형 모델 (휴리스틱 대체), 여러 사람 중 *누가* 눈을 감았는지
- [ ] 주 피사체 기준 초점 (얼굴 없는 사진: 돌출도 영역의 선명도)
- [ ] 의도한 흔들림(패닝 · 장노출)과 실수 구분
- [ ] 이유 설명 개선: "B컷 92% — 왼쪽 인물 눈 감음, 같은 순간에 더 나은 컷 있음"

### M4 — 속도 · 규모
- [ ] 분석 속도: RAW 내장 미리보기 디코딩 최적화, 배치 추론, Apple Silicon 가속(Core ML / Metal) 검토
- [ ] 5만 장 이상 라이브러리, 점진 학습

### M5 — 제품화 (유료 앱)
- [ ] Apple Developer ID 서명 + 공증 (유료 배포에 사실상 필수, 현재 CI 에 준비됨)
- [ ] 라이선스 키 · 활성화(오프라인 허용), 무료 체험(예: 사진 n장 / n일)
- [ ] 자동 업데이트, 오류 보고(옵트인)
- [ ] 랜딩 페이지 · 비교 데모(같은 촬영본을 기본 기준 vs 학습으로)

## 4. 데이터와 라이선스 주의

- 공개 미학 · 품질 데이터셋(AVA, AADB, KonIQ-10k, SPAQ 등)과 눈 감음 데이터셋(CEW 등)은 **연구용 · 비상업 조건인 경우가 많습니다.** 이걸로 학습한 모델을 유료 앱에 넣으려면 라이선스를 하나씩 확인하거나 직접 모은 데이터를 써야 합니다.
- 사전 학습 가중치도 같습니다: 지금 쓰는 YuNet(MIT) · MobileNetV2(Apache-2.0)는 상업 사용 가능.
- 사진가에게서 데이터를 받을 때는 *무엇을 · 왜 · 얼마나 오래* 를 밝힌 명시적 동의, 그리고 가능하면 사진 대신 특징값만.

## 5. 경쟁 구도 (요약)

AI 셀렉 제품(예: Aftershoot, Narrative Select, FilterPixel)은 대부분 *구독형*, *영어권*, 일부는 *클라우드 처리*입니다. 우리 쪽에서 내세울 수 있는 점:

1. **기기 안 처리** — 사진이 밖으로 나가지 않음 (웨딩 · 인물 고객 사진에 중요)
2. **평소 셀렉이 곧 학습 + 장면별 기준** — 따로 라벨링하지 않음
3. **가져오기부터 작품 폴더까지 한 앱** — SD 카드 → 셀렉 → 작품 테마 → 라이트룸 작업 폴더
4. 한국어 우선, 한국 사진가 워크플로(웨딩 · 스냅 · 프로필)

가격 · 판매 방식(영구 라이선스 / 구독 / 무료 + 유료 기능)은 M5 전에 정합니다.
